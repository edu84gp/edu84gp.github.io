Proyecto 01 · Full Stack e IA

Aplika Jobs

Plataforma que automatiza la búsqueda de empleo con inteligencia artificial: reúne las ofertas y prepara tu CV y carta para cada candidatura.

Problema

Buscar empleo termina siendo un proceso largo y tedioso. Cada día accedes a varios portales, buscas entre cientos de ofertas y envías tu CV sin saber si lo leerá una persona o será descartado por un filtro ATS.

Qué hice

  • API REST con Express 5 y TypeScript, validación con Zod y errores tipados.
  • Persistencia con PostgreSQL, Supabase y Prisma 7, con migraciones y transacciones en las operaciones sensibles.
  • Motor de búsqueda con JSearch, deduplicación, caducidad y persistencia por lotes.
  • Orquestador de matching con umbral configurable, reintentos y creación de candidaturas.
  • Generación de CV ATS, carta y email con Groq y OpenAI como respaldo, aislada del dominio.
  • Autenticación JWT, RBAC, OAuth de Google y LinkedIn, y rate limiting con Redis.
  • Frontend con React, Vite y Tailwind.

Resultado

El backend cubre el ciclo completo: del CV y la oferta a la candidatura, el CV adaptado y la carta. Hay demo pública y un caso de estudio con arquitectura, decisiones y fragmentos saneados. No publico métricas de conversión porque no existe una medición controlada.

Aprendizaje

Límites transaccionales, idempotencia, contratos tipados y errores recuperables en un flujo con IA.

  • Node.js 20
  • TypeScript
  • Express 5
  • PostgreSQL
  • Prisma
  • Supabase
  • Redis
  • Groq
  • OpenAI
  • React
  • Vite

Proyecto 02 · Agentes e IA

AI Job Search Copilot

Sistema de agentes sobre opencode que convierte una oferta en un flujo reproducible: análisis, CV adaptado, carta, registro y preparación de la entrevista.

Problema

La búsqueda de empleo se reparte entre portales, hojas de cálculo y documentos sueltos. Cada oferta exige adaptar el CV, escribir la carta, registrar el envío y preparar la entrevista sin un proceso repetible.

Qué hice

  • 15 agentes con permisos acotados por herramienta y 10 servidores MCP.
  • 20 comandos y 14 skills para cubrir el pipeline completo.
  • Registro de candidaturas en SQLite como fuente única, con agenda y seguimiento.
  • Generación y verificación del CV en DOCX y PDF.
  • Workflow de GitHub Actions para Markdown y enlaces.

Resultado

Lo uso a diario para buscar ofertas, adaptar el CV y registrar candidaturas. El repositorio es público y la CI está en verde. No hay métricas de entrevistas ni de conversión.

Aprendizaje

Diseño de agentes con privilegios limitados, separación entre instrucciones y herramientas, reproducibilidad y automatización con control humano.

  • opencode
  • MCP
  • Node.js
  • Python
  • SQLite
  • GitHub Actions
  • Playwright

Proyecto 03 · Frontend sin framework

Pokédex Web

Pokédex que consume la PokéAPI y muestra todos los Pokémon en un grid paginado con ficha de detalle.

Problema

Practicar el consumo de una API REST real con paginación y detalle, y construir una pieza de portfolio frontend sin depender de un framework.

Qué hice

  • Módulos separados de API, interfaz y controlador.
  • 30 Pokémon por página y paginación calculada con el total que devuelve la PokéAPI, con peticiones en paralelo mediante Promise.all.
  • Modal de detalle con estadísticas, habilidades y tipos.
  • Color por tipo, diseño responsive y manejo de errores.

Resultado

La demo pública recorre todos los Pokémon de la PokéAPI, con ficha de detalle. El README documenta la arquitectura y el flujo de datos.

Aprendizaje

Separación de responsabilidades, peticiones asíncronas en paralelo, renderizado del DOM y casos borde de paginación.

  • HTML5
  • CSS3
  • JavaScript ES6+
  • PokéAPI
  • GitHub Pages

Proyecto 04 · Algoritmos y accesibilidad

El Juego de la Vida

Simulador del autómata de Conway en JavaScript vanilla, con tablero configurable, edición de células y navegación por teclado.

Problema

Practicar algoritmos, estado matricial, renderizado del DOM y accesibilidad sin dependencias ni framework.

Qué hice

  • Reglas B3/S23 sobre una matriz finita y vecindario de Moore.
  • Tablero de 30×30 configurable entre 1×1 y 99×99, con patrón aleatorio.
  • Clic, Enter y Espacio para alternar células; flechas, Inicio y Fin para navegar.
  • Tablero accesible con role="grid", celdas gridcell, roving tabindex y región de estado.
  • Despliegue de main en GitHub Pages con GitHub Actions.

Resultado

La demo pública permite editar el tablero, generar patrones y ajustar la velocidad. El README documenta las decisiones y los límites. No hay pruebas automatizadas ni auditoría formal de accesibilidad.

Aprendizaje

Separar lógica y UI con módulos ES, calcular sobre una copia, delegación de eventos y navegación por teclado con un único tab stop.

  • HTML5
  • CSS3
  • JavaScript vanilla
  • GitHub Actions
  • GitHub Pages
